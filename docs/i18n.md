# Internationalisation (i18n) Architecture & Launch Guide

This document defines the internationalisation system for **onlineinvoicecreator.com** and provides a comprehensive, 10-step checklist for launching new languages (`pt-BR`, `es`, `fr`, `de`, or future locales) without impacting English SEO, URLs, or ranking signals.

---

## Architecture Overview

The internationalisation architecture is engineered to support incremental language rollouts with strict search engine safety:

1. **Astro Native i18n (`astro.config.mjs`)**:
   - `defaultLocale: 'en'`
   - `locales: ['en', 'pt-br', 'es', 'fr', 'de']`
   - `routing.prefixDefaultLocale: false` (English URLs have no `/en/` prefix, remaining byte-for-byte identical to original deployment).

2. **Locale Registry (`src/i18n/config.ts`)**:
   - Defines native language names (e.g., `Português (Brasil)`, `Español`, `Français`, `Deutsch`).
   - Per-locale formatting configuration (default currency code, number/date formatting locale, OpenGraph locale).
   - Gatekeeping via `published: boolean`: unpublished locales are completely invisible in the sitemap, hreflang tags, language switcher, and header navigation.

3. **Canonical Route Registry (`src/i18n/routes.ts`)**:
   - Maps 19 canonical route keys (tools, templates, guides, company, legal) to translated slugs for all 5 languages.
   - Enforces unique slugs per locale and `trailingSlash: 'never'`.
   - Generates bidirectional hreflang alternates with `x-default` pointing to English.

4. **100% Dictionary Key Parity (`src/i18n/*.json`)**:
   - Build-time validation script (`scripts/check-i18n-dictionaries.mjs`) fails the build if any non-English dictionary is missing a key present in `en.json`.

5. **Locale-Aware Formatting (`src/i18n/format.ts`)**:
   - Uses native `Intl.NumberFormat` and `Intl.DateTimeFormat`.
   - Prevents hardcoded thousand separators or decimal dots.

6. **PDF Latin Extended Font Verification (`tests/pdf-latin-extended.test.ts`)**:
   - Ensures correct encoding of accented glyphs (`ã õ ç é ê í ó ú á à â ñ ¿ ¡ ü ö ä ß œ « » € R$`) and French narrow no-break space (`\u202F`) in PDF exports.

## 10-Step Guide: Launching a New Language

Follow these 10 steps to publish an existing prepared language (e.g., `pt-BR`) or add a new locale to production:

### Step 1: Review Locale Registration in `src/i18n/config.ts`
Open [src/i18n/config.ts](file:///Users/vinodkumar/Desktop/playground/invoice%20generator/onlineinvoicecreator.com/src/i18n/config.ts) and verify the locale configuration:
```typescript
'pt-br': {
  code: 'pt-br',
  name: 'Português (Brasil)',
  lang: 'pt-BR',
  dir: 'ltr',
  published: false, // Set to true when ready to launch
  defaultCurrency: 'BRL',
  regionalFormatting: 'pt-BR',
  ogLocale: 'pt_BR',
}
```
- Verify the native name is written in its own language.
- Confirm standard BCP-47 language tag (e.g., `pt-BR`, `es-ES`, `fr-FR`, `de-DE`).
- Check default currency (e.g., `BRL` for Brazil, `EUR` for France/Germany).

---

### Step 2: Confirm Route Slugs in `src/i18n/routes.ts`
Open [src/i18n/routes.ts](file:///Users/vinodkumar/Desktop/playground/invoice%20generator/onlineinvoicecreator.com/src/i18n/routes.ts) and check that all 19 canonical keys map to their approved localized slugs:
```typescript
receipt: {
  en: 'free-online-receipt-generator',
  'pt-br': 'gerador-de-recibo',
  es: 'generador-de-recibos',
  fr: 'generateur-de-recu',
  de: 'quittung-erstellen',
},
```
> [!IMPORTANT]
> Never invent arbitrary slugs. Slugs must reflect localized organic search intent and must be unique within each locale.

---

### Step 3: Populate & Review Dictionary Strings in `src/i18n/<locale>.json`
Open the target dictionary file (e.g., [src/i18n/pt-br.json](file:///Users/vinodkumar/Desktop/playground/invoice%20generator/onlineinvoicecreator.com/src/i18n/pt-br.json)).
- Ensure all 131 keys are accurately translated.
- Ensure interpolation parameters (`{year}`, `{domain}`, `{targetLang}`) match `en.json`.
- Keep technical brand names (`PDF`, `PNG`, `JSON`, `Excel`) intact.

---

### Step 4: Run Dictionary Parity Build Check
Execute the automated key check script:
```bash
npm run check:i18n
```
The script scans every key in `src/i18n/en.json` and asserts 100% presence in all locale files. If a single key is missing or misspelled, it exits with code 1 and pinpoints the missing key.

---

### Step 5: Test PDF Latin Extended & Currency Glyph Support
Validate that standard PDF engines can render all special characters and currency symbols:
```bash
npx vitest run tests/pdf-latin-extended.test.ts
```
This tests:
- Portuguese: `ã`, `õ`, `ç`, `é`, `ê`, `í`, `ó`, `ú`, `R$`
- Spanish: `¿`, `¡`, `ñ`, `á`, `é`, `í`, `ó`, `ú`, `€`
- French: `é`, `è`, `ê`, `ç`, `œ`, `«`, `»`, `\u202F` (narrow non-breaking space), `€`
- German: `ä`, `ö`, `ü`, `ß`, `€`

---

### Step 6: Create or Enable Localized Astro Pages
To generate static pages for the new language:
1. Place localized `.astro` page files under `src/pages/<locale>/` or configure dynamic routes.
2. Ensure pages import layout components using the active locale:
```astro
---
import BaseLayout from '../../layouts/BaseLayout.astro';
import { getDictionary } from '../../i18n';

const locale = 'pt-br';
const d = getDictionary(locale);
---
<BaseLayout
  title={d.tools.freeOnlineReceiptGenerator}
  description={d.tools.freeOnlineReceiptGeneratorDesc}
  canonicalPath="/pt-br/gerador-de-recibo"
>
  <!-- Localized content -->
</BaseLayout>
```

---

### Step 7: Flip the `published` Flag to `true`
When translated content and pages are finalized, open [src/i18n/config.ts](file:///Users/vinodkumar/Desktop/playground/invoice%20generator/onlineinvoicecreator.com/src/i18n/config.ts) and set:
```typescript
'pt-br': {
  ...
  published: true, // Activated for production crawling and indexing
}
```
Setting `published: true` automatically:
- Surfaces the language in the header Language Switcher.
- Generates bidirectional `hreflang` alternate tags for the language across all pages.
- Adds localized URLs to `@astrojs/sitemap` (`dist/sitemap-index.xml`).
- Enables the client-side browser language suggestion banner.

---

### Step 8: Validate Hreflang Reciprocity & Canonical SEO
Run the comprehensive i18n test suite:
```bash
npx vitest run tests/routes-i18n.test.ts
```
This validates:
- **Hreflang Reciprocity**: If English points to Portuguese, Portuguese points back to English.
- **x-default**: Points to the English URL.
- **Self-referencing Canonical**: Every localized page has an absolute canonical pointing to itself (e.g. `https://onlineinvoicecreator.com/pt-br/...`), NEVER cross-canonicalized to English.
- **Title and Description Limits**: Titles $\le$ 60 characters, descriptions $\le$ 155 characters.
- **Valid JSON-LD**: `inLanguage` matches the locale BCP-47 tag.

---

### Step 9: Build and Inspect Sitemap
Execute a full production build:
```bash
npm run build
```
Verify the output:
1. Check `dist/sitemap-index.xml` and `dist/sitemap-0.xml`.
2. Verify `xhtml:link rel="alternate"` tags appear with the correct `hreflang` attributes.
3. Confirm no unpublished locales leak into the sitemap.

---

### Step 10: Dispatch Fast Indexing via IndexNow
Submit the newly published URLs directly to search engines (Bing, Yandex, Naver, Seznam):
```bash
npm run indexnow
```
Or force submission of all indexable URLs:
```bash
node scripts/submit-indexnow.mjs --all
```
This immediately notifies search engine crawlers of the new language pages without waiting for standard crawling passes.
